🕳️ GAP — Hệ thống đang thiếu gì

Kết quả audit toàn bộ codebase. P0 = phải sửa trước khi lấy số liệu báo cáo · P1 = quan trọng · P2 = có thể chờ. Bấm "Cách làm" để xem hướng dẫn cụ thể.

P0

GAP-1 · Metric collision bị "ói" sai (false positive)

👤 M4 · 📁 simulator/environment.py · ⏱ ~2h · Robot bị tính va chạm khi còn cách vật cản 0.35–0.40 m → mọi số collision trong corridor/obstacles đang bị thổi phồng
Cách làm →

Ngưỡng hiện tại: radius 0.15 + resolution/2 0.25 = 0.4 m tính tới tâm ô vật cản.

  1. Trong check_collision(): đổi so sánh khoảng cách tới biên ô gần nhất thay vì tâm ô (trừ thêm resolution/2).
  2. Thêm metric mới safety_margin_violations: đếm số bước có min_obstacle_distance < margin (cấu hình được, vd 0.3 m).
  3. Chạy lại --batch --save-results, so sánh collision trước/sau — this là kết quả nghiên cứu đầu tiên của nhóm.
P0

GAP-2 · Không có test bảo vệ map/scenario

👤 M2 · 📁 tests/ · ⏱ ~2h · 2 bug YAML (map corridor sai cú pháp, goal out-of-bounds) đã lọt qua vì không test nào load chúng
Cách làm →
  1. Tạo tests/test_scenarios.py: đọc configs/scenarios.yaml, với mỗi scenario: yaml.safe_load map tương ứng.
  2. Assert: start/goal nằm trong biên grid, không đè lên vật cản, A* tìm được đường.
  3. Chạy pytest — giờ bug YAML sẽ bị bắt ngay khi CI/test chạy.
P1

GAP-3 · Batch runner giòn + chạy im lặng

👤 M1 · 📁 evaluation/batch_runner.py · ⏱ ~1h · 1 map hỏng từng làm sập cả 12 lượt batch; không có tiến trình in ra → không biết đang chạy đến đâu (~8–13s/run)
Cách làm →
  1. Bọc thân mỗi lượt chạy trong try/except Exception → ghi nhận dòng "FAILED" thay vì crash cả batch.
  2. Trước mỗi run: print(f"[{i}/{n}] {scenario} × {config} ...", flush=True).
P1

GAP-4 · CLI --config/--variant bị hứa nhưng chưa làm

👤 M1 · 📁 run_pipeline.py · ⏱ ~1.5h · README và comment trong mpc_tuning.yaml đều nhắc flag này nhưng chạy sẽ báo lỗi unrecognized
Cách làm →
  1. Trong run_pipeline.py thêm 2 argument argparse: --variant (tên variant trong mpc_tuning.yaml, mặc định baseline) và --config (đường dẫn file YAML tùy chỉnh).
  2. Load variant → merge đè lên baseline → chạy như thường.
  3. Test: python run_pipeline.py --scenario corridor --variant conservative.
P1

GAP-5 · Variant aggressive làm collision tăng vọt

👤 M3 · 📁 configs/mpc_tuning.yaml · ⏱ ~3h · Corridor: 24 → 67 collision khi đổi baseline → aggressive. Chưa hiểu rõ nguyên nhân = chưa có bài học
Cách làm →
  1. Chạy corridor với cả 2 variant, lưu --save-log.
  2. Vẽ min_obstacle_distance theo thời gian — aggressive "cắt cua" sát hơn ở đoạn nào?
  3. Kết luận: Q/R trade-off + đề xuất variant "aggressive_safe" (giảm max_speed, giữ Q cao). Đây là 1 kết luận NCKH hoàn chỉnh.
P2

GAP-6 · Chỉ có A* — chưa có planner để so sánh

👤 M2 · 📁 planner/ · ⏱ ~4h · Nghiên cứu cần đối chứng (baseline vs phương pháp)
Cách làm →
  1. Dijkstra = A* với heuristic trả 0 — thêm cờ heuristic="none" vào astar().
  2. So sánh: số node mở rộng, thời gian, độ dài đường trên 3 map có sẵn.
P2

GAP-7 · requirements.txt chưa pin version

👤 M1 · 📁 requirements.txt · ⏱ ~0.5h · Cài hôm nay và 6 tháng sau có thể ra 2 môi trường khác nhau
Cách làm →
  1. Chạy pip freeze trong venv → copy đúng version của numpy/cvxpy/scipy/pandas/pyyaml/matplotlib vào requirements.
  2. Đổi >= thành ==.
P2

GAP-8 · Agent là rule-based, chưa phải AI thật

👤 M5 · 📁 agent/prompts.py · ⏱ ~6h · build_prompt() đã sinh prompt hoàn chỉnh nhưng chưa ai gọi LLM với nó
Cách làm →
  1. Thêm hàm suggest_with_llm(prompt) gọi LLM API (OpenAI/Anthropic) parse JSON trả về.
  2. Fallback về rule-based khi không có API key. MCP validation vẫn chặn mọi config nguy hiểm.
  3. So sánh: agent rule-based vs LLM — bao nhiêu trial để đạt goal? → kết quả NCKH thứ 2.
